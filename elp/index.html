Multimodal Overview & Contributions (Image · Text · Video)

One Executable Program-Search Framework Across Image, Text, and Video

Reusing transformer blocks through loops can improve pretrained models without updating their weights. However, useful loops require coordinated choices about which blocks repeat, how hidden states evolve, and when computation is reused. We introduce Evolving Loop Programs (ELP), an offline LLM-based method for discovering executable inference programs with favorable quality–compute trade-offs.

The search jointly edits loop structure, state-update dynamics, and execution controls—including sampling schedules, guidance, and intermediate-state reuse. The LLM writes diagnostic code and combines observations of model behavior with accumulated development evaluations to guide these edits. We retain nondominated programs for different operating priorities and freeze their code and parameters; during deployment, these frozen programs execute without further search-LLM calls. Across image generation (Scale-RAE, RAE, Looped-DiT-B32), text reasoning (Qwen3-4B, Dory1.0-4B), and video world models & diffusion (LongLive 2.0, LongLive 1.0, Self-Forcing, Wan2.1), ELP discovers specialized loop rules that consistently improve quality–compute Pareto frontiers.

Methodology

Four-Component Closed-Loop Program Search

All LLM search and diagnostic overhead occurs once offline per backbone. At deployment, selected programs run deterministically inside the frozen model with zero search-LLM calls.

Overview of Evolving Loop Programs (ELP). The coordinator executes candidate loop programs, records programmable diagnostics and metrics on a development split, and feeds back non-dominated Pareto frontiers so the search LLM refines structure, dynamics, and control across rounds.

1. What to Search: Loop Programs

Structure · Dynamics · Control

Each candidate p = (c, λ) pairs executable code c with settings λ, generalizing fixed block repetition to conditional, scheduled, and state-reusing recurrence.

st(k+1) = Uθ,p(st(k); t, k) Eq. (2)

2. What to Observe: Programmable Diagnostics

Runtime Traces

The search LLM authors diagnostic collectors Dr to inspect activation similarity across repetitions, guidance divergence, and inter-step residual stability on dev inputs.

𝓞r(p) = Dr( Traceθ(p, 𝓧dev) ) Eq. (3)

3. How to Search: Evidence-Guided Evolution

Offline Refinement

At round r, the LLM proposes candidate batch 𝒫r+1 from accumulated history, prior failures, and diagnostic observations guided by target vector a.

𝓟r+1 = LLM(𝓒r, 𝓗r, 𝓞≤r; a) Eq. (4)

4. What to Evaluate & Select: Pareto Priorities

Frozen Deployment

Non-dominated fronts track task metrics alongside latency speedup T(p0)/T(p). Representative Speed, Balanced, and Quality programs are frozen for test evaluation.

v(p) = (q1(p), …, qm(p), T(p0)/T(p)) Eq. (5)
